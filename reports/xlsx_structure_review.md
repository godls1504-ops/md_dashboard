## 4. 위험 점검 결과

### 4.1 ID 앞자리 0 손실
- **위험 낮음**: 모든 키 ID가 알파벳 접두(CAT/P/S/CH/WH/PR/IP/PO/RC/O/OI/AT/RT/PA/AC/V) → 숫자 앞자리 0 없음. 앞자리 0 문자열 **0건** 검출.
- **예외 주의**:
  - `sku_master.바코드`(전 399건 숫자 문자열, 13자리) — 리더/파서가 숫자로 인식하면 앞자리 손실·정밀도 문제 가능.
  - `receipt.송장번호`(`INV-YYYYMMDD-####`)는 문자열이라 안전하나 대시(-) 포함, 숫자 파싱 대상 아님.

### 4.2 날짜 혼합 형식
- **혼합 형식 없음**: 검출된 모든 날짜 문자열이 `YYYY-MM-DD` 단일 패턴(구분자 `-`).
- **단, 두 가지 주의**:
  1. **전부 문자열 저장**(엑셀 날짜 자료형 아님) → 분석 시 `pd.to_datetime(...)` 명시 파싱 필요.
  2. **날짜형/일시형 혼재**: 같은 데이터셋 안에 `날짜만`(예: 발주일) vs `날짜+시:분`(등록일시) vs `날짜+시:분:초`(주문일시, applied_at) 컬럼이 공존 → 파싱 포맷을 컬럼별로 지정.
  3. **기준일 이후 값 존재**: `order_item.cancel_date`(~2026-08-02), `returns.처리일`(~2026-08-06)이 분석 기준일(2026-07-31)을 넘어감 → 기준일 컷오프 정의 필요(Q4).

### 4.3 숫자형 ID 변환 위험
- **최우선: `sku_master.바코드`** — 숫자 문자열. 자동 형 추론 시 int64/float 변환되어 표시·조인·정밀도 문제 유발 가능. **문자열 유지 권장(로딩 시 dtype 지정)**.
- **자료형 혼재로 dtype 흔들림**:
  - `order_attribution.attribution_weight` = 정수 6,340 + 실수 1,130 (멀티터치 분할 가중치).
  - `traffic_daily.attributed_order_credit` = 실수 543 + 정수 362.
  - `sku_master.사이즈` = 문자(S/M/L) + 숫자 문자열 혼재.
- 이들 열은 로딩 시 **명시적 dtype/파싱 정책**이 없으면 시트/청크마다 다르게 추론될 수 있음.

### 4.4 중복 열 이름
- **시트 내 중복 없음**(전 시트 헤더 유일).
- 시트 **간** 동일 열명은 정상적으로 존재(`sku_id`, `warehouse_id`, `channel_id`, `정상가`, `상품상태` 등) — 조인·의미상 의도된 것. 병합 시 접미사 정책만 유의.

### 4.5 숨김 시트 가능성
- **없음**: 19개 시트 상태 전수 확인 결과 전부 `visible`. `hidden`·`veryHidden` 0개. 워크북 외 숨김 정의 미발견.
